# L002: Unbalanced blocks

| Property | Value |
| --- | --- |
| Severity | error |
| Fixable | no |
| Source | [Error: No match for endfor](../../skills/micros-isl-language/isl-reference/reference/errors.md#no-match-for-endfor), [Error: No match for endwhile](../../skills/micros-isl-language/isl-reference/reference/errors.md#no-match-for-endwhile), [Error: Unmatched endevent](../../skills/micros-isl-language/isl-reference/reference/errors.md#unmatched-endevent), [Error: Unmatched if](../../skills/micros-isl-language/isl-reference/reference/errors.md#unmatched-if), [Error: Break without endfor](../../skills/micros-isl-language/isl-reference/reference/errors.md#break-without-endfor) |

A block opener (`event`, `sub`, `if`, `for`, `forever`, `while`, `startprint`) with no matching closer, a closer with no opener or the wrong opener, `else`/`elseif` outside an `if`, or `break` outside a loop.

## Why

ISL matches each closer with the innermost open block. A missing `endif` or `endfor` is the most common cause of "Unmatched" and "No match for" errors, and the message points far from the cause.

## Bad

```isl
event init
  if a
endevent
```

## Good

```isl
event init
  if a
  endif
endevent
```

## Limits

After an unclosed block the linter resynchronises at the next `event` or `sub`, so one slip is reported once. A `sub` inside an event is rule [L014](L014.md).
